# 0.13.1 live smoke

Build: `release/0.13.1`. Log: `%LOCALAPPDATA%\626Labs\RoRoRoUrTask\logs\ur-task.log`.

Every fix in 0.13.1 is covered by a unit test, and none of them has been seen working in the
running app. This list is the part only a person at the machine can do. Tick each box, and where a
line asks for something to be written down, write it here.

Sections 1 to 4 decide whether 0.13.1 ships. Section 5 is one finding that was held out of the
build until it is seen live. Section 6 is quick looks.

## Setup

- [ ] Your main plus at least 2 alts in PS99 on the private server.
- [ ] Quit the installed Ur Task from its tray icon and start the branch build, or install the
      branch build over 0.13.0.
- [ ] The log's start line reads `RoRoRo Ur Task v0.13.1`. If it says 0.13.0 the run is void.
- [ ] The start of the log has a "Hotkeys ready" line, or one line per hotkey that another program
      is using. Write down any that failed: ____

## 1. The stop keys

- [ ] **Hold Ctrl+Shift+P for a full second.** Keep-alive starts and stays on. The log has one
      "Playing assignments" line and no "stopped (Ctrl+Shift+P toggle)" line after it.
- [ ] **Double-click PLAY ASSIGNMENTS.** The loop starts and stays on.
- [ ] **Esc stops an agent's repeat.** Have an agent (or the Ur MCP `run_macro` tool) run any macro
      on one account with `repeat: true`. Press Esc while it plays. It stops, and it does not start
      again half a second later. Repeat with Ctrl+Shift+F12.
- [ ] **A repeat on a closed window gives up.** Start the same repeat, then close that account's
      Roblox window. The playback ends as failed and names the account. CPU does not climb and the
      log does not fill.
- [ ] **Quit mid-hold.** Run a macro that holds W, then Quit from the tray during the hold. The
      character stops walking.
- [ ] **After a stop, the window says so.** With keep-alive running, press Esc. Every keep-alive
      row flips to "stopped" at once, and the tray tooltip reads "keep-alive is off".

## 2. Keep-alive

- [ ] **Limits follow the game.** Launch an alt AFTER Ur Task has connected. Within about a minute
      the activity list says "<name> is in Pet Simulator 99: keep-alive now uses its 15-minute
      limit." `keepalive_status` shows a deadline about 9 minutes after its last input, not 12.
      Write down what it shows: ____
- [ ] **A late joiner is served.** Press Ctrl+Shift+P and launch an alt in the same few seconds.
      Every account, the new one included, gets its Space when due. No "service failed" line
      repeats in the log.
- [ ] **Switching an account back on works at once.** With the loop running and nothing due, turn
      "Keep-alive off" on for one account, wait until it is past its deadline, turn it back off.
      It gets its Space within a few seconds.

## 3. Recording

- [ ] **Recording pauses keep-alive.** With keep-alive running, press Ctrl+Shift+R on an alt. The
      activity list says keep-alive is paused. Record a few keys, stop. It says keep-alive is back
      on, and the rows count down again.
- [ ] **No stray Spaces.** Open the macro you just recorded. It contains only the keys you pressed.
- [ ] **Ctrl+Shift+P is refused while recording**, with a line telling you to stop recording first.
- [ ] **Keys typed elsewhere are not recorded.** Start a per-window recording, alt-tab to Notepad,
      type a word, come back, press one key in the game, stop. The macro holds the one game key
      and none of the word.
- [ ] **The warning fires.** Start a recording with an alt already 8 or 9 minutes idle and leave
      it running until the activity list names that alt and a time. Then stop. (Optional if short
      on time: this path is unit-tested, and the cost of skipping is not seeing the wording.)
- [ ] **Break-glass and recording.** Keep-alive on, press Ctrl+Shift+F11, start a recording, press
      Ctrl+Shift+F11 again, stop the recording. Keep-alive comes back.

## 4. Where clicks land

- [ ] **A covered click is refused.** Put Ur Task's compact window over the spot a mouse macro
      clicks in an alt, and play the macro on that alt. It stops with "Another window is covering
      the spot…" and does not click Ur Task.
- [ ] **An overlay does not trip it.** With an in-game overlay showing (Discord, Xbox Game Bar, or
      a GPU overlay), play the same macro with nothing else over the spot. It clicks as before.
      Write down which overlay you tried: ____
- [ ] **A key-only macro leaves the window alone.** Play a macro that has only keys and waits on
      an alt whose window is a different size from the recording. It plays, and the window does
      not move or resize.

## 5. Held out of the build: L1-01

Not fixed in 0.13.1. This check decides whether it needs fixing.

- [ ] Two accounts, Turbo keep-alive on. Leave account A in front and not due. Let a sweep serve
      account B. Then read `keepalive_status` for A.
      - A's last-input time is unchanged: the finding is not real. Close it.
      - A's last-input time jumped to the moment of the sweep: RoRoRo credited A for Ur Task's own
        input, and A will now be served late. It goes into 0.13.2.
      Write down which: ____

## 6. Quick looks

- [ ] PLAY ASSIGNMENTS is enabled as soon as the first account row appears, with no hotkey press.
- [ ] Right-click a macro: "Export as AutoHotkey v1…" and "v2…" are both there and open a save
      dialog. "Allow in all games" shows a tick when on.
- [ ] Pick a routine, tick an account, click RUN: the button reads STOP while it runs, and
      clicking it stops the routine.
- [ ] Rename a macro whose file you have just edited by hand (change a wait, save the file,
      then rename it in the window). The file keeps your edit.
- [ ] Run a two-account sequence (pick a macro, play it on two alts). The window switches to
      compact while it runs. If it does not, write that down: it settles which of two review
      findings (L6-05, L3-06) is the real one. ____
