# 0.13.0 live smoke

Build: `feat/0.13.0-wave-a`, `bin\Debug\net10.0-windows\626labs.ur-task.exe`. Log:
`%LOCALAPPDATA%\626Labs\RoRoRoUrTask\logs\ur-task.log`.

## Setup

- [ ] Your main plus at least 2 alts running in PS99 on the private server, every one assigned
      **keep-alive**. Keep-alive stays on for every account for the whole check; nothing gets
      idle-kicked.
- [ ] Install over 0.12.1 (or quit the installed Ur Task from its tray icon and start the branch
      build).
- [ ] The log's start line must read `RoRoRo Ur Task v0.13.0`. If it says 0.12.1 the run is void.

## 1. Permissions (install over 0.12.1)

- [ ] RoRoRo asks about two new permissions: reading account activity, and marking an account
      active. Note the exact wording RoRoRo shows for each: ____
- [ ] Grant both. The "next" times in the window come from real idle, and starting keep-alive
      does not jump every account at once: an account you touched in the last few minutes waits
      for its deadline, and only accounts with no input anywhere go first, a couple of seconds
      apart.
- [ ] Decline both once (reinstall or revoke), restart Ur Task. Keep-alive still runs on its own
      clock and nothing is idle-kicked.

## 2. Miss explains itself, then recovers

Run this section twice: once with **Turbo keep-alive** on and once with it off.

- [ ] Type in another app while an account comes due. The miss line names the refusal and the
      holder: `Windows refused focus while '<title>' (<process>) was in front`. A recovery line
      (`landed again after N misses`) follows when it lands again.
- [ ] Turbo on: the per-alt `turbo keep-alive: skipped <alt>, …` lines read exactly as in 0.12.1;
      when the whole sweep is refused by one window there is one extra line,
      `keep-alive: every due account missed: Windows refused focus while '…' was in front`.
- [ ] Turbo off: several accounts refused by one window give that same single
      `every due account missed` line, not one per account.
- [ ] Keep the other app in front past an account's deadline until a retry can't land before
      the limit. One line says "expect a reset or kick around HH:mm". It does not appear on an
      ordinary miss that still has runway.
- [ ] Close one alt's window during a due time. The line says the window is gone.

## 3. Pause and pick up

- [ ] Run a long macro on one account while another reaches its deadline.
- [ ] The macro pauses at a step boundary, the other account jumps, and the macro resumes at the
      same step. The log shows the pause and the resume.
- [ ] Optional: a macro with a long hold and no max near a deadline may be stopped, with advice.

## 4. Keep-alive off, per account

- [ ] Switch **Keep-alive off** on one alt. It shows `off` in `GetStatus` and is never focused.
- [ ] Turn it back on. It rejoins the loop and is served at its deadline.
- [ ] Switch it off again, then restart Ur Task. It comes back on (off lasts only until a
      restart) and rejoins the loop.
- [ ] Launch another account while keep-alive runs. It joins the loop without a restart.

## 5. Agent view

- [ ] `keepalive_status` from Ur MCP 0.5.0 matches what the window shows: running, per-account
      idle and deadline, which are off, paused playbacks.
- [ ] A macro file that can't be read is refused with `macro-unreadable`, with an advice line.

## 6. Game limits

- [ ] An idle PS99 account's deadline reads about 9 minutes after its last input (15 minutes
      limit minus 6).
