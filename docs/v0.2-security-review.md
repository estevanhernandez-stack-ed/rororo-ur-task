# v0.2 — Security Review

**Date:** 2026-05-11
**Scope:** Deployment security of `.github/workflows/release.yml`, dependency audit, secrets scan.

## Dependency audit (I4)

Ran `dotnet list package --vulnerable --include-transitive` on both projects.

- `rororo-ur-task.csproj` — **no vulnerable packages**.
- `rororo-ur-task.Tests.csproj` — **no vulnerable packages**.

Only NU1603 warnings: ROROROblox sibling project requests `Grpc.Net.Client >= 2.68.0` but the resolver picked `2.70.0`. Newer is fine — non-issue.

## Secrets scan (I3)

Worked tree + git history scanned for `api_key`, `aws_secret`, `password =`, `bearer <hex>`, `ghp_`, `sk_live`, `sk_test`, and similar patterns. **Zero hits.** Only false positives were `CancellationToken` (a .NET type that contains the substring "token").

`.gitignore` covers `*.env`, `.env.local`, `secrets/` from v0.1.

## Deployment security (I5)

`.github/workflows/release.yml` review:

| Check | Status | Notes |
|---|---|---|
| Pinned action versions | ✅ | All actions use major-version pinning (`@v4`, `@v2`). Not full SHA, but no `@main`/`@master`. Acceptable for a personal-scale project. |
| Minimal permissions | ✅ | `permissions: contents: write` only. No broader scopes. |
| Trigger scope | ✅ | `push: tags: ['v*']` + manual `workflow_dispatch`. Random commits don't trigger releases. |
| No expression injection | ✅ | All `${{ }}` expressions read `github.ref_name` (safe, comes from the tag name). No untrusted user input flows to shell commands. |
| Sibling repo checkout | ✅ | Fixed `repository: estevanhernandez-stack-ed/ROROROblox`. Tracks `main` after v1.4 merged — no `feat/plugin-system` override remaining. |
| Code signing | ⚠️ | Not addressed in v0.1 or v0.2. Consistent with v0.1 — not a regression. Velopack handles update signing; the EXE itself isn't code-signed. Future work if needed. |
| Action SHA pinning | ⚠️ | Could be hardened with full commit SHAs per CIS GitHub Actions benchmark. Not a vulnerability — acceptable for v0.2. |

## Verdict

**Clean.** No regressions from v0.1's release workflow. No new attack surface introduced by v0.2 changes (no new secrets, no new outbound calls, no new exec surfaces).

Two hardening opportunities flagged (code signing, action SHA pinning) — both out of scope for v0.2.
