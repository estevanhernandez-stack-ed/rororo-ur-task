# RoRoRo Ur Task v0.2 — Design Spec

**Status:** Approved, ready for implementation plan
**Author:** Brainstormed with Este, 2026-05-11
**Supersedes:** v0.1.0 (shipped 2026-05-11)
**Unblocks:** Discord clan announcement of RoRoRo v1.4 (held until v0.2 ships portable + multi-window)

---

## 0. Why v0.2

v0.1.0 shipped portable, working per-window macros — but every macro was bound to a single Roblox user-id at record time. Record "jump-jump" on Goldnail8, you couldn't play it on PinkPotatoChip. That constraint shipped the plugin system but couldn't carry a clan demo.

v0.2 makes macros **portable** (record once, play on any alt), adds **multi-select sequential playback** ("run this macro on 8 alts in sequence"), adds an opt-in **multi-window recording** mode for flow macros that switch alts themselves, redesigns the recorder UI to fit the richer playback shape, fixes the **bare-F5/F8 global hotkey hijack**, and adds a **compact watching view** so the alt windows stay visible during sequence playback.

When v0.2 ships, the v1.4 clan announcement unblocks.

## 1. Architecture & component changes

### New components

| Component | Path | Role |
|---|---|---|
| `MacroV1Migrator` | `src/Macros/MacroV1Migrator.cs` | Pure function, load-time. Converts v1 `Macro` records to v2 in memory. Migration is sticky — re-saving writes v2 shape. |
| `PlaybackTargetPicker` | `src/UI/PlaybackTargetPicker.cs` + `PlaybackTargetPickerWindow.xaml` | Modal window for picking target alt(s). Single-select and multi-select-sequential modes. Reused by both per-macro PLAY click and `Ctrl+Shift+P` fallback. |
| `SequencePlayer` | `src/Macros/SequencePlayer.cs` | Orchestrates `MacroPlayer` across N alts in click order. Owns batch state; `MacroPlayer` stays single-alt and stateless. Emits `SequenceProgress` event stream. |
| Sequence-run + compact-mode state | (state on `RecorderViewModel` + `Visibility` triggers in `RecorderWindow.xaml`) | Not separate components — `RecorderViewModel` gains `SequenceProgress` / `IsCompact` / `IsTopmost` observable properties; the XAML grid rows collapse via Visibility bindings. Single window, two layouts. |

### Renamed / signature changes

- `MacroPlayer.PlayAsync(Macro macro, CancellationToken ct)` → `MacroPlayer.PlayAsync(Macro macro, long targetUserId, CancellationToken ct)`. The target user-id is a parameter now, not derived from the macro.
- `AutoStopCoordinator` watches the **resolved target user-id** (passed at play start), not a bound user-id.
- `PluginRuntime.TriggerPlay()` → `PluginRuntime.TriggerPlayLast()` (smart-default hotkey path) and `PluginRuntime.TriggerPlayMacro(Guid id)` (per-card PLAY click).
- `RecorderViewModel.PlayCommand` (plays last) becomes `PlayLastCommand`; new `PlayMacroCommand` (RelayCommand<Macro>) for per-card invocation.

### Retired

- `Macro.BoundUserId` / `BoundAccountId` / `BoundDisplayName` fields (replaced by `RecordedAgainstUserId` / `RecordedAgainstDisplayName` — informational, not enforced).
- Row 1 of `RecorderWindow.xaml` ("FOREGROUND WINDOW" border + `BoundForegroundLabel` binding) — informational widget for v0.1's binding model, no longer load-bearing.
- `RecorderViewModel.BoundForegroundLabel` property and the 250ms `_foregroundTimer` polling. The target picker resolves foreground on-demand at click time; no continuous polling needed.
- `PLAY LAST` button — every macro card has its own `PLAY` now.

## 2. Macro shape + v1 migration

### v2 envelope (`src/Macros/Macro.cs`)

```csharp
public sealed record Macro(
    int SchemaVersion,                 // = 2
    string Id,
    string? Name,
    string? RecordMode,                // "PerWindow" | "AllWindows" — new in v2
    long? RecordedAgainstUserId,       // soft metadata, not enforced
    string? RecordedAgainstDisplayName,
    int? InterAltDelayMs,              // per-macro override; null → use SequencePlayer default (500)
    long RecordedAtUnixMs,
    IReadOnlyList<MacroEvent> Events)
{
    public const int CurrentSchemaVersion = 2;
    public TimeSpan Duration => /* unchanged */;
}
```

`RecordedAgainstDisplayName` stays in v2 so the recorder card can show `▶ Goldnail8` as a hint of where the macro was recorded — but it's metadata, not enforcement.

### Migration semantics

On `MacroStore.LoadAll()`, the JSON deserializer reads any schema version. If `SchemaVersion == 1`:

- `BoundUserId` → `RecordedAgainstUserId`
- `BoundDisplayName` → `RecordedAgainstDisplayName`
- `BoundAccountId` dropped (not used in v2)
- `RecordMode` set to `"PerWindow"` (v1 was always per-window)
- `InterAltDelayMs` set to `null`
- Migration is sticky — on next write of any kind, the file persists in v2 shape. Never destructive on read alone.

Card UI surfaces migrated v1 macros with a `V1 · ScrambledTen` legacy tag (uses `RecordedAgainstDisplayName`) so the user can tell which macros pre-date the portable model.

### Migration test fixture

- `tests/fixtures/macro-v1.json` — frozen v1 JSON blob (a real v0.1 macro).
- `MacroV1MigrationTests.cs` — assert `MacroStore.LoadAll()` returns it as v2, that `RecordedAgainst*` fields are populated from `Bound*`, and that re-saving writes v2 shape with the legacy fields gone.

## 3. Single-alt playback flow

### Trigger paths

- **`Ctrl+Shift+P` hotkey** (play last macro) → smart-default.
  - If `ForegroundWatcher.ResolveForegroundAccount()` returns a RoRoRo-managed alt: play directly on that alt. One call to `MacroPlayer.PlayAsync(lastMacro, fg.RobloxUserId, ct)`.
  - If foreground isn't a RoRoRo alt: open `PlaybackTargetPicker` in single-select mode; on selection, play. On Esc, no-op.
- **Per-macro card `PLAY` click** → always opens `PlaybackTargetPicker`. User picks single OR multi each time. Single = same `MacroPlayer.PlayAsync` call. Multi routes into `SequencePlayer` (section 4).

### Picker behavior — single-select

- Sticky title: `"Play <macro name> on which alt?"` plus subtitle.
- Sticky footer: `"Esc to cancel · ↑↓ to move · ↵ to play"` — visible regardless of scroll position.
- Pre-selected row: foreground alt if any; else "last played here" alt; else top of list. Enter plays the highlighted alt.
- ↑↓ keyboard nav; single-click on a row plays immediately (no confirm).
- Scrolls when alt count exceeds visible space — designed for 6–10 visible, scales to dozens.
- Modal child of the recorder window; auto-closes when recorder closes.

### Mid-playback abort

- `AutoStopCoordinator` watches the resolved target's pid via `AccountRegistry.AccountRemoved`. If it fires, `MacroPlayer.Abort()`.
- Foreground shifting mid-play to a non-target window aborts (unchanged from v0.1, but checked against `targetUserId` not `BoundUserId`).
- `Esc` global hotkey calls `MacroPlayer.Abort()`.

### Hotkey shape (changed from v0.1)

| Action | v0.1 | v0.2 | Scope |
|---|---|---|---|
| Record/Stop | `F8` (bare) | `Ctrl+Shift+R` | Global (`HotkeyService`) |
| Play last | `F5` (bare) | `Ctrl+Shift+P` | Global (`HotkeyService`) |
| Abort | `Esc` (bare) | `Esc` (unchanged) | Global (`HotkeyService`) |
| Compact toggle | — | `Ctrl+Shift+M` | **Window-level** (XAML `<KeyBinding>` on `RecorderWindow`) |

Reason: bare `F5`/`F8` global hotkeys hijack those keys system-wide while Ur Task runs (browser refresh, IDE reload, Roblox Studio play). TinyTask's modern default is chord combos for the same reason — the v0.1 comment that bare F-keys "match TinyTask muscle memory" was wrong.

In `HotkeyService.cs`, `RegisterHotKey(... fsModifiers: MOD_CONTROL | MOD_SHIFT, vk: VK_R/VK_P)`. `Esc` stays bare. The v0.1 comment block referencing TinyTask muscle memory updates to reflect reality.

`Ctrl+Shift+M` is **window-level only** — registered as a `KeyBinding` on `RecorderWindow` (or the compact strip when in that mode), not via `HotkeyService`. It's only meaningful while the recorder is the focused app; no need to hijack it system-wide.

`RegisteredVkCodes` filter in `MacroRecorder` only skips `VK_R`/`VK_P` **when Ctrl+Shift is held** — otherwise lowercase typing of those letters gets eaten.

## 4. Multi-select sequential playback engine

### `SequencePlayer` public contract

```csharp
public async Task<SequenceResult> PlayAsync(
    Macro macro,
    IReadOnlyList<AccountInfo> orderedTargets,   // alt 1, 2, ... in click order
    int interAltDelayMs,                          // macro.InterAltDelayMs ?? 500
    CancellationToken external = default);

public event EventHandler<SequenceProgress>? Progress;

public sealed record SequenceProgress(
    int Index, int Total,
    AccountInfo CurrentAlt,
    SequencePhase Phase,    // Focusing | Playing | Settling | Aborted
    int Completed, int Failed, int Skipped);

public sealed record SequenceResult(
    IReadOnlyList<AltOutcome> PerAlt,
    int Completed, int Failed, int Skipped,
    TimeSpan TotalDuration);

public sealed record AltOutcome(
    AccountInfo Alt,
    PlaybackOutcome Outcome,   // Completed | Refused | Aborted | Skipped
    string? Reason);
```

### Loop body, per target

1. Emit `SequenceProgress(Index: i, Phase: Focusing)`.
2. Resolve `targets[i].Pid` → `MainWindowHandle` via `Process.GetProcessById(pid).MainWindowHandle` (re-resolved each iteration; window handles can change if Roblox recreates the main window). Call `SetForegroundWindow(hwnd)`. Wait `interAltDelayMs` (default 500ms — gives Roblox time to register focus and gives the user time to see the switch). If `Process.GetProcessById` throws (pid is gone), record failure for this alt and continue to next.
3. Verify foreground actually flipped: `ForegroundWatcher.ResolveForegroundAccount()` must return `targets[i].RobloxUserId`. If not, record failure for this alt with reason `"Couldn't focus <name> — window may be minimized or frozen"`, **continue to next** (skip-on-failure).
4. Emit `SequenceProgress(Phase: Playing)`. Call `MacroPlayer.PlayAsync(macro, targets[i].RobloxUserId, _internalCts.Token)`. Capture `PlaybackResult`.
5. If `Outcome == Refused | Aborted` → log inline, **continue to next**. If `Completed` → log success.

### Global abort (`Esc` during sequence)

- Cancel active `MacroPlayer` via `_internalCts.Cancel()`. Mark remaining targets as `Skipped (sequence aborted)`. Emit `SequenceProgress(Phase: Aborted)`. Return.

### End-of-sequence summary

Recorder window shows a banner for ~6s after sequence ends: `"jump-jump: 4/5 succeeded — ScrambledTen window closed."` Click banner to expand to per-alt breakdown (matches activity log narration).

### Order indicator in picker modal

- Numeric tag (1, 2, 3…) on each selected row in click order.
- Unchecking a middle row re-numbers the rest.
- `SequencePlayer` receives the targets list in exactly that order.

### Selection state

Selection is **fresh each time the picker opens**. No saved target groups in v0.2 — that's a v0.3 follow-up.

## 5. Multi-window recording mode

### Background

v0.1's `MacroRecorder` already uses global low-level hooks (`WH_KEYBOARD_LL`, `WH_MOUSE_LL`) — captures all keyboard/mouse events system-wide regardless of foreground. The per-window-ness in v0.1 was always a **playback** gate, not a record-time gate. So this section is smaller than the v0.1 handoff implied.

### `RecordMode` enum

```csharp
public enum RecordMode { PerWindow, AllWindows }
```

Stored on `Macro.RecordMode` (nullable string in v2 schema, defaults to `"PerWindow"` when missing — see section 2 migration).

### Toggle UI

Thin pill row in the recorder window between the RECORD button row and the macros list. Label: `"Record across all windows"` + small `EXPERIMENTAL` tag. Persistent (until app close). When ON, label color turns cyan and the recorder header shows a `MULTI-WINDOW` chip inline with the title so the mode never gets forgotten. Hidden/disabled while a recording is in flight (can't toggle mid-record).

### At record time

- Mode is captured from the toggle state when `MacroRecorder.Start()` is called and stored on the resulting macro.
- Recorder behavior is unchanged either way (hooks are already global). The mode is metadata about *intent*.

### At play time

- **`PerWindow` macros** → use the target picker (single or multi-select per sections 3/4).
- **`AllWindows` macros** → skip the picker entirely. First play of the session pops a one-time pre-flight modal:

  > *"This macro plays back input across multiple windows as recorded. Make sure your alt windows are in their original positions and order. The macro will switch focus itself."*

  OK / Cancel. After OK, plays raw events with no foreground gating and no auto-stop. Subsequent plays in the same session skip the warning.

- AllWindows macros render with the `MULTI-WINDOW` tag on their card so they're visually distinct.

### Auto-stop semantics for `AllWindows`

`AutoStopCoordinator` is bypassed for AllWindows playback (no single target window to watch). `Esc` still aborts immediately.

## 6. Recorder window UI redesign

### Layout (top → bottom in `RecorderWindow.xaml`)

1. **Header** — eyebrow `"RORORO UR TASK"` + title `"Macros"`. When `RecordMode == AllWindows` is active, a `MULTI-WINDOW` chip appears inline so the mode never gets forgotten. Pin icon (📌) toggles `Window.Topmost`. Compact icon (⌐) toggles compact mode.
2. **Status pill** — replaces v0.1's separate "FOREGROUND WINDOW" and "STATE" widgets. Single row with dot + label + meta. Four skins:
   - **Idle** — grey dot, `"Idle"`, `"N macros"`.
   - **Recording** — magenta dot (glowing), `"Recording"`, `"0:14 · 47 events"`.
   - **Playing single** — cyan dot, `"Playing jump-jump on Goldnail8"`, `"1.4s remaining"`.
   - **Playing sequence** — cyan dot, `"Playing jump-jump on PinkPotatoChip"`, `"alt 3 of 8 · 1.4s remaining · 4 succeeded, 0 failed"`, plus a thin gradient progress bar (overall sequence completion).
3. **Two big buttons** — `RECORD` (`Ctrl+Shift+R`, becomes `STOP` while recording) + `ABORT` (`Esc`). `PLAY LAST` retires.
4. **Multi-window toggle pill** — `"Record across all windows"` + `EXPERIMENTAL` tag. When ON, label turns cyan ("Recording across all windows"). Hidden during in-flight recordings.
5. **Macros area** — scrollable card list. Each card:
   - Name, `PLAY` button (cyan), `⋯` overflow menu (Rename / Delete / Set inter-alt delay / Convert to v2 if legacy).
   - Meta row: event count, duration, one tag chip — target hint (`▶ Goldnail8`), legacy (`V1 · ScrambledTen`), or `MULTI-WINDOW`.
   - Currently-playing card outlined cyan with `PLAYING` replacing `PLAY`. Other cards dim during sequence playback.
6. **Empty state** — when `Macros.Count == 0`, replace the list with a centered hint: `"Hit Ctrl+Shift+R or RECORD to capture your first macro"` in muted text. No fake cards, no placeholder content.
7. **Activity log** — kept from v0.1, mono font, 4–5 lines visible. Narrates per-alt sequence outcomes inline (`"alt 2 (ScrambledTen) skipped — window closed at event 8"` in warning color).
8. **Footer** — connection status. Unchanged from v0.1.

### Compact mode

- **Trigger:** `⌐` icon in header, or `Ctrl+Shift+M` hotkey, or auto-collapse on sequence start.
- **Shape:** ~360×80 always-on-top strip. Single row containing: dot + (alt name + progress meta + thin progress bar) + ABORT button + expand button (`⌐` flipped). Distilled from the full status pill.
- **Auto-collapse on sequence start, auto-expand on sequence end.** Single-alt plays don't auto-collapse (too brief). Overflow-menu option to disable auto-collapse if it gets annoying.
- **Position:** freely draggable, top-right at first launch, remembered between sessions.
- **Pin (Topmost) state:** independent per-mode. Compact defaults `Topmost = true`; full defaults `Topmost = false`. Each pin state persists separately.
- **Implementation:** single `RecorderWindow.xaml` with `IsCompact` viewmodel flag; rows 4–8 of the main Grid collapse via `Visibility` binding when compact. Window resize animated over 150ms.

### Viewmodel additions (`RecorderViewModel.cs`)

- `SequenceProgress` (observable) — bound to `SequencePlayer`'s event stream. Drives status-pill skin + progress bar + per-card "PLAYING" indicator.
- `RecordMode` (toggle binding) — two-way to `_runtime.RecordMode`.
- `IsCompact` (bool, two-way) — drives layout collapse + window resize.
- `IsTopmost` (bool, two-way) — drives `Window.Topmost`, persisted separately per-mode.
- `PlayMacroCommand` (RelayCommand<Macro>) — invoked from per-card `PLAY` button.
- `IsSequencePlaying` derived from `SequenceProgress != null && Phase != Aborted/Done`.

### Window size

Full mode keeps `520×640`. Compact mode `360×80`. New layout fits with breathing room because two v0.1 rows (foreground-bind + state-pill separate) collapse into one (status pill).

## 8. Decision log (to mirror to 626 dashboard at session end)

| Topic | Decision | Why |
|---|---|---|
| Target picker behavior | Smart default + fallback modal | Zero friction on common path; explicit choice when foreground is ambiguous |
| V1 migration | Auto-convert on load, drop binding | No data loss, no migration UI, soft `RecordedAgainstDisplayName` preserves the "I recorded this on Goldnail8" hint |
| Multi-window mode | Persistent toggle, resets on app close | Power-user feature, explicit visual indicator, no per-record re-arming |
| Multi-select playback | YES (added to v0.2) | "Play on all 8 alts" is the most common power-user ask; legitimate scope expansion |
| Multi-trigger | Per-macro PLAY always opens modal; `Ctrl+Shift+P` stays smart-default | Click = deliberate, hotkey = fast — two paths, two defaults |
| Failure mid-sequence | Skip failed alt, continue, summary at end | Closest to user intent (run on whoever's still around) |
| Inter-alt delay | 500ms default + per-macro override | Mac instance flash-too-quick problem says hard pause matters; override surface handles future tuning |
| Hotkey shape | Switch to chord defaults (`Ctrl+Shift+R/P`, Esc bare) | Bare F5/F8 hijack system-wide keys; TinyTask uses chord defaults for the same reason |
| Compact mode | Yes — always-on-top strip, auto-collapse on sequence start | Roblox alts need to be visible while the macro sweeps them; recorder window hides them in full mode |
| Compact pin | Toggle, per-mode persistence | Compact defaults pinned (whole point is staying visible); full defaults unpinned (don't be obnoxious) |
