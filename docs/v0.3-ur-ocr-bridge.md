# v0.3 — Ur OCR → Ur Task bridge (A3 contract sketch)

**Status:** proposal · sketched 2026-05-16
**Companion repo:** [`Ur-OCR`](https://github.com/estevanhernandez-stack-ed/Ur-OCR)
**Decision context:** see decision log entry "Ur OCR fires Ur Task macros — pick A3 over capability duplication"

## Goal

Let an Ur OCR trigger fire a *specific* Ur Task macro on a *specific* set of alts, without duplicating the macro engine into Ur OCR. Ur Task stays the only place that owns playback; Ur OCR stays a thin trigger watcher.

## Probe first (A2)

Ship before A3: add a "Press Ctrl+Shift+P" preset to Ur OCR's keybind picker. Confirms the UX is real before we cut a contract. One macro slot only ("last macro"); good enough for the "one OCR trigger, one repeated flow" use case. If A2 covers 80% of the use case, A3 can wait.

## Transport

**Named pipe, current-user only.** `\\.\pipe\626labs-ur-task` — server lives in the Ur Task process, accepts a single concurrent connection.

- SDDL: owner = current user, no other principals on the ACL. Reject impersonation tokens.
- Loopback-only by construction (named pipes don't leave the machine).
- Not a new declared capability — same-user, same-machine IPC initiated by a sibling plugin doesn't cross a system surface. Document it in the consent sheet anyway ("Accepts macro-run requests from other 626 Labs plugins on this PC").

Alternative considered: localhost HTTP on 127.0.0.1:<random>. Rejected — needs port discovery, firewall prompts on first run, and gains nothing over a pipe for local-only traffic.

## Wire format

JSON over length-prefixed frames. 4-byte big-endian length, then UTF-8 JSON. Same shape both directions.

Why not gRPC: we already use gRPC for the *host* connection (`PluginClient.cs`), but that's because the host owns the contract. For a plugin-to-plugin call where we own both sides, the cost of a `.proto` + codegen pipeline isn't paid back by anything. JSON keeps the contract debuggable from a one-line PowerShell probe.

## Request shape

```json
{
  "contractVersion": "1.0",
  "method": "RunMacro",
  "macroId": "f4e5d6c7-...-...",
  "targets": [123456789, 987654321],
  "interAltDelayMs": 500,
  "callerPluginId": "626labs.ur-ocr"
}
```

- `macroId` — Guid string. Matches a file at `%LOCALAPPDATA%\626Labs\RoRoRoUrTask\macros\<id>.json`.
- `targets` — *optional*. Ordered list of Roblox user-ids. Null/omitted = smart-default (foreground alt at the moment of the call, mirrors the `Ctrl+Shift+P` semantics).
- `interAltDelayMs` — optional override for `SequencePlayer`. Null = use the macro's own `InterAltDelayMs`, or the 500ms default.
- `callerPluginId` — for the activity log; refuse if missing or unknown.

## Response shape

Sync ack on accept/refuse, fire-and-forget after:

```json
{
  "ok": true,
  "playbackId": "01ARZ3...",
  "queued": false
}
```

or refusal:

```json
{
  "ok": false,
  "reason": "busy" | "unknown-macro" | "no-targets-resolved" | "refused" | "version-mismatch",
  "detail": "Sequence already running (playbackId 01ARZ2...)"
}
```

**No streaming progress in v1.** If/when Ur OCR wants per-alt feedback it can subscribe to a second pipe; for the first version, "we accepted it, watch the activity log" is enough.

**Busy semantics:** if Ur Task is mid-sequence, refuse with `busy` — do *not* queue. Queueing creates surprise on next foreground change, and OCR triggers are edge-triggered with cooldowns so a re-fire is cheap.

## Discovery: how Ur OCR builds the picker

Ur OCR reads `%LOCALAPPDATA%\626Labs\RoRoRoUrTask\macros\*.json` directly, parses the v2 envelope, surfaces `Id` + `Name` + `RecordedAgainstDisplayName` in the trigger edit panel. Read-only. No new IPC method needed for listing.

Justification: the macros directory is already the durable contract for the v2 format (`MacroStore.cs:39`). If Ur Task ever moves macros out of disk JSON, both plugins update — same as today.

## Lifecycle

- **Ur Task not running** → pipe doesn't exist → `NamedPipeClientStream.ConnectAsync` times out. Ur OCR logs `blocked: ur-task-not-running` in the activity log and falls back to the trigger's keybind if one is set, otherwise no-ops. **Never auto-launch Ur Task from Ur OCR** — the user starts plugins, plugins don't start each other.
- **Ur Task starts mid-session** → next OCR trigger that asks for a macro succeeds. No reconnect storm; one connection attempt per fire.
- **Pipe disconnect mid-call** → Ur Task aborts the sequence (treats it like Esc abort) and logs the cause.

## Ur OCR side — abstraction

Today:

```csharp
public interface IKeyPress { void Press(KeyCombo combo); }
```

Becomes:

```csharp
public interface IFireAction { Task FireAsync(Trigger trigger, CancellationToken ct); }

public sealed class KeyChordFireAction : IFireAction { /* today's KeySender path */ }
public sealed class RunMacroFireAction : IFireAction { /* the new pipe client */ }
```

`Trigger` grows a discriminated `Action` field (KeyChord | RunMacro) — schema v2 of `triggers.json` with a one-shot migrator. KeyCombo stays for the KeyChord branch.

## Ur Task side — server wiring

- New `Ipc\MacroRunnerServer.cs` — owns the `NamedPipeServerStream`, accepts one client at a time, deserializes requests, calls into a method on the existing `SequencePlayer` instance.
- Hosted on a dedicated background thread; cancellation hooked into app shutdown.
- Reuses `AccountRegistry` to resolve `targets` (user-ids) → `(Pid, Hwnd)` tuples for `SequencePlayer`.

No changes to `MacroStore`, `MacroPlayer`, or `SequencePlayer`. Surface area is one new file plus a wire-up in `App.xaml.cs` / `MainWindow`.

## Versioning

`contractVersion` in every request. Ur Task refuses anything outside `1.x`. Bump the minor on additive fields; bump major if we ever break a field name.

## Open questions

- **Consent flow** — does the consent sheet at install time need to mention "this plugin will accept run requests from other plugins"? Lean yes, surface it on Ur Task's install screen even though it's not a system capability.
- **Cross-plugin telemetry** — do `RunMacro` invocations from Ur OCR show up in Ur Task's activity log with the caller plugin id? Yes, the request carries `callerPluginId` for exactly this.
- **Should `targets` accept "foreground alt" as a sentinel** (`["foreground"]`) instead of null? Probably cleaner, decide before shipping.

## Implementation order

1. **A2 probe** — Ur OCR ships "Ctrl+Shift+P" as a keybind preset. Validate the UX.
2. **Ur Task server** — `MacroRunnerServer.cs` + tests against an in-process pipe pair. No Ur OCR dependency yet.
3. **Ur Task UI** — settings toggle "Accept run requests from other plugins" (default on, can be disabled).
4. **Ur OCR client** — `RunMacroFireAction` + UI toggle in the trigger edit panel + macros-directory reader.
5. **End-to-end** on one trigger before shipping.
